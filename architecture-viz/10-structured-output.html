Phase V · Advanced Inference

10 · Controlling the Output: Sampling, Constrained Decoding & Tool Calls

A language model gives you a probability distribution over ~150k tokens, once per step. Everything an inference server does to shape that distribution — temperature, penalties, JSON-schema grammars, tool-call formats — happens in a few hundred microseconds between the last matmul and the sampling kernel. This chapter follows the logits from SamplingParams through penalties and grammar bitmasks to the sampler, then up through the OpenAI-compatible layer where tool calls and reasoning tags are parsed back out.

10.1The sampling pipeline, end to end

Every request carries a SamplingParams — a msgspec.Struct, kw_only=True, array_like=True (python/sglang/srt/sampling/sampling_params.py:45), not a pydantic model: it is serialized over ZMQ for every request, so it uses the fastest struct library available. The key fields and their defaults:

Per-request params are useless to a GPU; the scheduler batches them. SamplingBatchInfo.from_schedule_batch (python/sglang/srt/sampling/sampling_batch_info.py:86) builds pinned-memory tensors — temperatures (B,1), top_ps, top_ks (int32), min_ps — plus fast-path flags (is_all_greedy = all top_k <= 1, need_top_p_sampling, need_top_k_sampling, need_min_p_sampling), a dense (B, V) logit_bias tensor only if any request set one, and custom logit processors deduped by their serialized string with a boolean row mask each. As continuous batching adds and removes requests (chapter 02), merge_batch / filter_batch concatenate / index the same tensors so row i always matches request i.

Exactly four penalizers, lazily materialized BatchedPenalizerOrchestrator is always constructed with all four penalizer classes from python/sglang/srt/sampling/penaltylib/ — frequency, presence, repetition, min_new_tokens — but each self-gates via _is_required() (e.g. any frequency_penalty != 0.0 in the batch), so an unpenalized batch pays only for the checks. Frequency/presence are additive with scatter_add_-accumulated counts; min_new_tokens adds -inf on stop tokens; repetition is the only multiplicative one. For the overlap scheduler, copy_for_forward() snapshots penalties into acc_additive_penalties / acc_scaling_penalties tensors and drops the orchestrator, which only holds a weakref to the batch (sampling_batch_info.py:454). 
@torch.compile(dynamic=True, backend=get_compiler_backend(), disable=_is_npu)
def apply_scaling_penalties(logits, scaling_penalties):
    logits[:] = torch.where(
        logits < 0,
        logits * scaling_penalties,
        logits / scaling_penalties,
    )

The exact application order lives in one function:

    def apply_logits_bias(self, logits: torch.Tensor):

10.2Constrained decoding: backends & the GrammarManager

Constrained decoding exists because "please answer in JSON" is a suggestion, while a grammar bitmask is a proof: at each step the matcher computes which tokens can extend a valid parse and every other logit becomes -inf. SGLang ships three backends under python/sglang/srt/constrained/, selected by --grammar-backend:

BackendFileSupportsNotes
xgrammar (default)xgrammar_backend.py json · regex · ebnf · structural_tag Only backend with is_support_token_filter=True — required for --enable-strict-thinking. Pinned-CPU int32 bitmask, Triton/HIP apply kernels.
outlinesoutlines_backend.py json · regex JSON is converted to a regex via build_regex_from_schema; ebnf/structural_tag dispatch to _not_supported. Boolean mask + masked_fill_(-inf).
llguidancellguidance_backend.py json · regex · ebnf · structural_tag LLMatcher/LLExecutor; native batched bitmask fill including speculative draft chains (GrammarDraftRow).
none——Grammar requests are aborted with an error. Custom backends can be added via register_grammar_backend.

If --reasoning-parser is set and the model has think_end_ids, the chosen backend is wrapped in a ReasonerGrammarBackend (constrained/reasoner_grammar_backend.py): the inner grammar stays dormant while the model is inside <think>…</think>, and a thinking budget (custom_params["thinking_budget"] or SGLANG_MAX_THINK_TOKENS) can force the think section closed. So "JSON output from a reasoning model" works without constraining the chain of thought.

Compilation is expensive (a big JSON schema can take seconds), so the scheduler-side GrammarManager (python/sglang/srt/constrained/grammar_manager.py) never compiles inline. It builds a cache key ("json" | "regex" | "ebnf" | "structural_tag", key_string) (grammar_manager.py:144) and asks the backend:

10.3Where the masking actually happens

The grammar lives in the scheduler process, but logits live on the GPU in the model runner (they are the same OS process — see chapter 01 — but different subsystems). The split is: mask fill + apply happen in the forward path; FSM advance happens when results are processed. Three functions carry the whole mechanism: 

    def update_regex_vocab_mask(self):
        if not self.grammars:
            self.grammar_mask = None
            return

        first_grammar = next(grammar for grammar in self.grammars if grammar)

        vocab_mask = first_grammar.allocate_vocab_mask(
            vocab_size=self.vocab_size,
            batch_size=len(self.temperatures),
            device=self.device,
        )
        entries = [
            GrammarRow(row=row, grammar=grammar)
            for row, grammar in enumerate(self.grammars)
            if grammar and not grammar.finished and not grammar.is_terminated()
        ]
        first_grammar.fill_vocab_mask_batched(entries, vocab_mask)

        vocab_mask = first_grammar.move_vocab_mask(vocab_mask, self.device)
        self.grammar_mask = GrammarMask(first_grammar, vocab_mask)

    def _preprocess_logits(
        self, logits_output: LogitsProcessorOutput, sampling_info: SamplingBatchInfo
    ):
        # NOTE: In overlap mode, the function update_regex_vocab_mask (in sample)
        #       was executed after we processed last batch's results.

        # Calculate logits bias and apply it to next_token_logits.
        sampling_info.update_regex_vocab_mask()
        sampling_info.apply_logits_bias(logits_output.next_token_logits)

        # Release the vocab_mask GPU tensor immediately after it has been applied
        sampling_info.grammar_mask = None

    def _accept_grammar_tokens(
        self, req: Req, tokens: Union[int, List[int]]
    ) -> List[int]:
        if isinstance(tokens, int):
            tokens = [tokens]
        retained = []
        try:
            for token_id in tokens:
                req.grammar.accept_token(token_id)
                retained.append(token_id)
                if req.grammar.is_terminated():
                    break
        except ValueError as e:
            logger.error(
                f"Grammar accept_token failed for req {req.rid} with token "
                f"{tokens}: {e}"
            )
            req.to_finish = FINISH_ABORT()
        return retained

Speculative decoding (chapter 09) complicates step 3: a verified run of k draft tokens is accepted in one go, and rejected drafts are undone with grammar.rollback(k) — every GrammarMatcher is created with max_rollback_tokens=MAX_ROLLBACK_TOKENS=200 (xgrammar_backend.py:57). Tokens past grammar termination are dropped from the retained run so they are never committed to KV nor emitted.

Docs/paper drift: jump-forward decoding is vestigial here The SGLang paper's "compressed FSM" / jump-forward decoding (emitting multi-token constants like {"name": in one step) survives only as an orphaned API in this repo: try_jump_forward / jump_forward_str_state / jump_and_retokenize exist on every grammar object (base_grammar_backend.py, implemented in the xgrammar and outlines backends), but a repo-wide search finds no caller outside constrained/; the scheduler never invokes them, and OutlinesGrammarBackend._compile_regex hard-codes jump_forward_map = None (outlines_backend.py:157). outlines_jump_forward.py is retained but dead. The approach was superseded by xgrammar's fast batched bitmask fill.

10.5Function calling: detectors & the streaming state machine

Tool calling has two halves: constraining the output (so the model emits its native tool-call syntax) and parsing it back into OpenAI tool_calls deltas. Both are owned by FunctionCallParser (python/sglang/srt/function_call/function_call_parser.py:54), which wraps one of 33 registered detectors in ToolCallParserEnum: deepseekv3, deepseekv31, deepseekv32, deepseekv4, qwen/qwen25 (→ Qwen25Detector), qwen3_coder, glm/glm45/glm47, kimi_k2/kimi_k3, llama3 (→ Llama32Detector), mistral, gpt-oss, hermes, pythonic, minimax-m2/-m3, step3/step3p5, hunyuan, gemma4, inkling, and more — all extending BaseFormatDetector.

At request time, get_structure_constraint(tool_choice, parallel_tool_calls, thinking_mode) (function_call_parser.py:230) picks a decoding constraint by priority: (1) a model-native xgrammar structural tag from the detector (get_auto_tool_call_structural_tag / get_structural_tag), (2) the legacy structural-tag format — begin/end/trigger per tool, schema attached only when strict — and (3) for tool_choice="required" or a named tool on detectors without structural-tag support, a plain JSON-array json_schema constraint whose output is parsed by JsonArrayParser (json_array_parser.py:8) instead of the native detector. The streaming side makes the same choice per stream index by probing detector.supports_structural_tag() / parses_required_natively() (serving_chat.py:2324-2354). Strictness escalates globally via SGLANG_TOOL_STRICT_LEVEL.

Streaming parse is a little state machine in BaseFormatDetector.parse_streaming_increment (base_format_detector.py:125): accumulate chunks in self._buffer; if the buffer can't even be a partial bot_token, flush it as normal text; otherwise parse incrementally with partial_json_parser. The name is streamed first, as its own delta:

Arguments then stream as diffs: each parse re-serializes the partial arguments, computes the common prefix with the previous parse (_find_common_prefix), and emits only what hasn't been sent (tracked per tool in streamed_args_for_tool). 10.6Reasoning parser (the other parser)

Separate from function calling, python/sglang/srt/parser/reasoning_parser.py strips think-tags for reasoning models. ReasoningParser holds a DetectorMap of 25 model types (deepseek-r1, deepseek-v3/-v4, qwen3/qwen3-thinking, glm45, gpt-oss, kimi/kimi_k2/kimi_k3, mistral, minimax variants, step3/step3p5, nemotron_3, gemma4, inkling, cohere_command4, …), each knowing its think_start_token / think_end_token. Models like DeepSeek-R1 and gpt-oss set force_reasoning=True: output is treated as in-reasoning from token 0 because the opening tag never appears. In streaming, each choice index gets its own parser and each delta is split into reasoning_content vs content before the tool-call parser runs. Its scheduler-side twin is the ReasonerGrammarBackend from §10.2 — one strips tags in text, the other delays grammar enforcement until </think>.

10.9Notable facts & gotchas

  • Grammar compilation is consensus-synced: compile futures run on a per-backend ThreadPoolExecutor; under TP the ready set is the intersection across ranks and the failed set the union, and PP0 pushes the decision down the pipeline — no rank ever fills a mask from a grammar another rank hasn't compiled.
  • XGrammar bitmasks are pinned CPU memory filled by the matcher, then moved H2D with non_blocking=True — the comment in _allocate_token_bitmask (xgrammar_backend.py:60) notes a pageable source would silently degrade to a blocking copy. A -1 row means "all allowed".
  • Failures are cached too: an invalid schema compiles to an InvalidGrammarObject(error_message) which is cached, so repeated bad schemas fail instantly with the original compiler error.
  • The grammar mask is nulled right after applying (model_runner.py:1582) — under overlap scheduling the closure holding sampling_info survives to the next iteration, and keeping the mask alive was a steady VRAM leak.
  • A rejected token aborts the request: XGrammarGrammar.accept_token raises ValueError if the matcher rejects, and the scheduler converts that to FINISH_ABORT. With a correct mask this "can't happen" — it guards mask/FSM desync.
  • Custom logit processors travel as dill-hex inside JSON (CustomLogitProcessor.to_str), are deduped per batch by string hash, and are gated behind --enable-custom-logit-processor.
  • tool_choice="required" has two output regimes: native structural-tag output parsed by the model's detector, or a JSON-array constraint parsed by JsonArrayParser — chosen per stream by probing supports_structural_tag() / parses_required_natively().
  • User grammar beats tools: if a request sets its own json_schema/regex/ebnf/structural_tag and also has tools, the tool constraint is dropped with a warning "Constrained decoding is not compatible with tool calls" (protocol.py:1061).
  • finish_reason is rewritten: when tool calls were emitted, the final chunk's stop becomes tool_calls in serving_chat.py.
  • The gRPC servicer is out-of-repo (smg-grpc-servicer): in-repo remain only the proto, the sidecar wrapper, and the PyO3 RuntimeHandle the Rust gateway uses to reuse the exact same serving classes without HTTP.

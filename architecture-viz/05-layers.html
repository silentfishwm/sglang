Phase III · Models & Compute

05 · The Layer Library: Parallel Linear, MoE, Quantization, LoRA & Multimodal

Every one of the 212 model files in srt/models/ is a thin composition of a shared layer library in srt/layers/. That library is where tensor parallelism, MoE dispatch, quantization, LoRA, and multimodal embedding actually happen — a model file just names the pieces. Learn the library once and every model file becomes readable.

5.1A tour of srt/layers/

The design (inherited from Megatron via vLLM — many files carry Adapted from ... vllm headers — then heavily extended) has one governing idea: the layer owns sharding and communication; the quant method owns the math; the model file owns neither. A model constructor asks for a QKVParallelLinear and gets back a module that already knows its TP shard, its quantized weight format, and whether its forward ends in an all-reduce.

Everything is a MultiPlatformOp RMSNorm, the activations, RoPE, and MoE TopK are all MultiPlatformOps carrying up to eight per-platform forwards (forward_cuda / forward_npu / forward_hip / forward_aiter / forward_musa / forward_xpu / forward_cpu / forward_native), selected once at init. That is how one layer library serves NVIDIA, AMD, Ascend, MUSA, Intel and CPU builds without per-model forks.

5.2Tensor-parallel linear layers

Two primitives carry all of tensor parallelism, and the whole trick is choosing which dimension to cut so that communication is only needed once per pair:

  • ColumnParallelLinear (layers/linear.py:293) — Y = XA with A split along its output dimension, A = [A₁, …, A_p]. Every rank has the full input and computes its own slice of the output. No communication — as long as the next layer is happy consuming a sharded tensor (gather_output=True exists but is rarely used).
  • RowParallelLinear (layers/linear.py:1380) — A split along its input dimension. Each rank holds a slice of the input (exactly what the preceding ColumnParallel layer produced) and computes a partial full-width output; the partials are summed with an all-reduce. Bias is added only on rank 0 so it isn't summed p times.

On top of those come the fusions: MergedColumnParallelLinear (gate_proj+up_proj concatenated into one GEMM, output_sizes=[I, I]) and QKVParallelLinear (Q, K and V concatenated, sharded by attention head). For grouped-query attention, the KV heads run out before the ranks do — so they get replicated: 

self.num_heads = divide(self.total_num_heads, tp_size)
if tp_size >= self.total_num_kv_heads:
    self.num_kv_heads = 1
    self.num_kv_head_replicas = divide(tp_size, self.total_num_kv_heads)
else:
    self.num_kv_heads = divide(self.total_num_kv_heads, tp_size)
    self.num_kv_head_replicas = 1

A Llama-3-8B (8 KV heads) at TP=8 gives every rank exactly one KV head; at TP=16 each KV head is replicated on two ranks — and the KV cache is duplicated with it. This waste is one of the motivations for DP attention (chapter 07), which DeepSeek-style MLA models use to avoid splitting their single latent KV head at all.

Note how much policy hides in that one spot: the all-reduce can be skipped per call-site (skip_all_reduce), suppressed by per-forward flags when the runtime fuses it into the next RMSNorm or replaces it with a reduce-scatter (should_skip_mlp_all_reduce()), rerouted to the attention-TP subgroup under DP attention, or quantized on the wire for prefill (enable_quant_communications). VocabParallelEmbedding plays the same game on the vocab dimension: out-of-shard token ids are masked to zero locally and the partial embeddings are summed by all-reduce.

5.3MoE: one module, pluggable dispatch and compute

All MoE models instantiate a single module — FusedMoE (layers/moe/fused_moe_triton/layer.py:201; DeepEPMoE subclasses it). Its forward is a fixed five-stage pipeline in which two stages are plugins: the token dispatcher (how token activations reach the ranks that own their experts, --moe-a2a-backend) and the MoE runner (which grouped-GEMM implementation crunches them, --moe-runner-backend). Any of ~8 dispatchers can pair with any of ~11 runners.

DeepEP: two wire protocols, chosen per forward mode

The DeepEP dispatcher (layers/moe/token_dispatcher/deepep.py) has two implementations and DeepEPMode (moe/utils.py:177) = NORMAL | LOW_LATENCY | AUTO picks between them. AUTO.resolve(is_extend_in_batch) returns NORMAL for prefill (chunked NVLink+RDMA bulk transfers, throughput-optimal) and LOW_LATENCY for decode (IBGDA RDMA, fixed num_max_dispatch_tokens_per_rank, CUDA-graph-safe, returns async hooks for two-batch overlap). The low-latency path can quantize activations to FP8 — or NVFP4 — inside the all-to-all, halving wire bytes:

class QuantizeMethodBase(ABC):
    """Base class for different quantized methods."""

    def create_weights(
        self, layer: torch.nn.Module, *weight_args, **extra_weight_attrs
    ):
        """Create weights for a layer.

        The weights will be set as attributes of the layer."""
        raise NotImplementedError()

    @abstractmethod
    def apply(self, layer: torch.nn.Module, *args, **kwargs) -> torch.Tensor:
        """Apply the weights in layer to the input tensor.

        Expects create_weights to have been called before on the layer."""
        raise NotImplementedError()

5.5LoRA serving: fixed slots, chunked-SGMV kernels

Multi-LoRA serving is owned by LoRAManager (lora/lora_manager.py:59) inside each TP worker. Design: a fixed-slot GPU pool — LoRAMemoryPool (lora/mem_pool.py:131) preallocates unified A/B buffers shaped (max_loras_per_batch, max_lora_dim · c, input_dim) — into which adapters are swapped per batch (LRU/FIFO eviction). One batch can therefore mix up to --max-loras-per-batch (default 8) different adapters plus base-only requests, and adapters hot-load/unload at runtime via the /load_lora_adapter / /unload_lora_adapter HTTP endpoints (even from in-memory tensors, load_lora_adapter_from_tensors).

Model-side merge: managers/mm_utils.py — general_mm_embed_routine (:1252) runs only on extend batches containing mm inputs (decode steps skip it entirely), calls the model's get_image_feature, and embed_mm_inputs (:1011) writes the result into the text-embedding tensor. 5.8Notable facts & gotchas

  • Two all-reduces per layer is the whole TP bill — after o_proj and after down_proj. Everything else (column layers, activations, norms) is communication-free, and even those two can be fused, reduce-scattered, subgrouped, or quantized on the wire.
  • Dispatcher × runner is a free matrix: ~8 token dispatchers pair with ~11 MoE GEMM backends through the typed DispatchOutput/CombineInput interfaces — --moe-a2a-backend and --moe-runner-backend are independent knobs.
  • GQA replication doubles KV cache silently: once tp_size ≥ total_num_kv_heads, each extra doubling of TP replicates every KV head (and its cache) on more ranks — a key reason MLA models prefer DP attention (chapter 07).
  • Quant tensors are born sharded: create_weights receives input_size_per_partition / output_partition_sizes, so a marlin-repacked or block-fp8 tensor never exists in unsharded form on any rank.
  • DeepEP AUTO switches wire protocol per forward: chunked NVLink/RDMA NORMAL for prefill, IBGDA LOW_LATENCY (CUDA-graph-safe, fp8/nvfp4 on the wire, async recv hooks for two-batch overlap) for decode.
  • MoE experts can be paged like virtual memory: FusedMoE.forward_impl carries DWDP hooks (wait_prefetch / record_compute_and_prefetch_next) that stream expert weights from a page pool one layer ahead.
  • LoRA reaches places you'd not expect: FusedMoEWithLoRA and ParallelLMHeadWithLoRA exist; adapters hot-swap through HTTP endpoints into fixed pool slots without touching base weights.
  • Images are radix-cacheable: placeholder runs use hash-derived ids per image, so two requests sharing an image get a KV-cache prefix hit (chapter 03) even though the "tokens" are synthetic.
  • Adding a model = one file: drop my_model.py in srt/models/ with an EntryClass whose class name matches HF config.architectures — the registry scan does the rest (external packages can override via SGLANG_EXTERNAL_MODEL_PACKAGE).

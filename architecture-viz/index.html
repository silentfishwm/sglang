0.1What is SGLang?

SGLang is an open-source serving engine for large language models and vision-language models, built for production throughput. It began as a research project — the NeurIPS 2024 paper "SGLang: Efficient Execution of Structured Language Model Programs" introduced RadixAttention (automatic KV-cache prefix reuse via a radix tree) and a Python DSL for programming LLM interactions — and has grown into a full serving stack used at massive scale (xAI publicly serves Grok on SGLang; the project README reports deployments spanning hundreds of thousands of GPUs).

Four ideas define its character; everything else in this guide elaborates on them:

  • Continuous batching with a zero-overhead scheduler — requests join and leave GPU batches every iteration, and CPU scheduling work is overlapped with GPU execution so the GPU never waits (chapters 01–02).
  • RadixAttention — all KV cache lives in one radix tree keyed by token IDs, so any shared prefix (system prompts, few-shot examples, multi-turn history) is computed once and reused automatically (chapter 03).
  • A pluggable compute stack — 20+ attention backends, ~29 quantization methods, AOT/JIT/Triton kernel tiers, and platform abstraction spanning NVIDIA, AMD, Intel, Ascend, and more (chapters 04–06).
  • Scale-out by composition — TP/PP/DP/EP parallelism, DP attention for MLA models, prefill-decode disaggregation with RDMA KV transfer, hierarchical KV cache, and a Rust model gateway (chapters 07–08).
Scope & provenance This guide documents the code in this repository at the commit it was written against (45c00da, 2026-08). SGLang moves fast: several subsystems here are newer than, or renamed from, what upstream blog posts describe (e.g. the kernel tree now lives under python/sglang/kernels/, the router is now the "Model Gateway"). Where the repo and older public docs disagree, the pages follow the repo and call out the drift.

0.2Sixty seconds of LLM-inference background

Every chapter assumes you know this much: serving an autoregressive LLM has two very different phases, and nearly every architectural decision in SGLang exists to exploit that difference.

Prompt"What is the capital of France?"
KV cacheone entry per token per layer
Whatis thecapital ofFrance ? The capital is Paris
PREFILL — compute-boundall prompt tokens in parallel, one pass
DECODE — memory-bandwidth-boundone token per pass, reads the whole KV cache

Prefill saturates the GPU's compute units; decode barely uses them but hammers memory bandwidth. That asymmetry is why SGLang batches many requests' decode steps together (chapter 02), caches and shares prefill work (chapter 03), replays decode through CUDA graphs (chapter 04), speculates several tokens per pass (chapter 09), and can even run prefill and decode on separate GPU fleets (chapter 08).

12.1The metrics system: 120 series across three processes

Recall from chapter 01 that an SGLang server is several OS processes: the main process (HTTP + TokenizerManager), one scheduler subprocess per GPU rank, and a detokenizer. Metrics are recorded where the knowledge lives — queue depths and KV usage in the scheduler process, request latencies in the main process — and merged at scrape time using prometheus multiprocess mode: every process writes its counters into mmap shard files under PROMETHEUS_MULTIPROC_DIR, and the /metrics route in the main process aggregates all shards with a MultiProcessCollector.

def add_prometheus_middleware(app):
    # We need to import prometheus_client after setting the env variable `PROMETHEUS_MULTIPROC_DIR`
    from prometheus_client import CollectorRegistry, make_asgi_app, multiprocess

    registry = CollectorRegistry()
    multiprocess.MultiProcessCollector(registry)
    metrics_route = Mount("/metrics", make_asgi_app(registry=registry))

    # Workaround for 307 Redirect for /metrics
    metrics_route.path_regex = re.compile("^/metrics(?P<path>.*)$")
    app.routes.append(metrics_route)

Beyond Prometheus: tracing and push telemetry

  • OpenTelemetry tracing (observability/trace.py): enabled with --enable-trace --otlp-traces-endpoint .... It propagates incoming traceparent/tracestate headers (TRACE_HEADERS, trace.py:39) across all processes, so one request's spans in the tokenizer, scheduler, and detokenizer stitch into a single distributed trace. --trace-modules filters which subsystems emit spans (global_trace_modules), and the trace level is runtime-adjustable via the /set_trace_level endpoint. mooncake_trace.py adds KV-transfer stages (e.g. MOONCAKE_SEND) for PD disaggregation (chapter 08).
  • Per-iteration ZMQ telemetry (observability/forward_pass_metrics.py): with --enable-forward-pass-metrics the scheduler PUBs one msgspec-serialized ForwardPassMetrics per forward pass over localhost ZMQ. The docstring names the consumer explicitly: Dynamo's planner subscribes for polling-free real-time scheduler telemetry. The schema is versioned (FPM_VERSION = 1) and running stats use a WelfordAccumulator (numerically stable online variance).
  • Per-request records: observability/req_time_stats.py timestamps every stage of a request's life; request_metrics_exporter.py can JSON-export per-request perf records (always stripping image_data/video_data/ audio_data/input_embeds); utils/request_logger.py + the /configure_logging endpoint control runtime request logging and dumping.

12.3Configuration: from CLI flag to sealed config bag

SGLang's configuration story has three tiers. First, ServerArgs (python/sglang/srt/server_args.py, 9,392 lines) — a single dataclass holding every CLI flag. Each field is annotated A[type, help, NS("namespace")]; the NS() metadata assigns it to a runtime-context namespace, and arg_groups/arg_utils.py auto-derives the entire argparse CLI from these annotations. Second, ModelConfig is derived from it. Third, the resolved values are published into the process-global RuntimeContext as sealed, read-only namespace bags that business code actually reads.

ConfigArgumentMerger.merge_config_with_args() splices YAML keys into the arg list so CLI always wins. ModelConfig._derive_context_length (configs/model_config.py:760) computes context length from the HF config and loudly warns if a user-supplied --context-length exceeds it ("may lead to incorrect model outputs or CUDA errors"). publish() records the process role (tokenizer/scheduler/dp_controller/…) and is last-publish-wins; draft workers deliberately never publish.

The RuntimeContext singleton (runtime_context.py, reached via get_context()) organizes all process-static state into tiers, per the repo's sglang-runtime-context design:

  • Config bags — get_model(), get_schedule(), get_exec(), get_memory(), get_spec(), get_serving(), get_observability(), get_disagg(), get_lora(), get_mm(), get_device(). Bag leaves are real instance attributes so they trace cleanly under torch.compile. Sealed: the only post-publish write path is get_context().override(source, **fields), which logs provenance.
  • Pristine seed — get_server_args() returns the published ServerArgs verbatim, kept for debugging and dumps; business code must not branch on it.
  • Runtime flags — get_flags(): typed groups (capture/moe/dp) for derived-at-init state.
  • Resources — get_stream(name) (named CUDA side-stream leases like "alt", "offload"), get_buffer(name, factory).
  • Per-forward flags — get_forward(): contextvar-backed with transactional scoped(**kw).
  • Parallel — get_parallel(): live topology properties that win over config-bag leaves once torch.distributed is initialized.
    def __setattr__(self, name: str, value: Any) -> None:

CI-enforced discipline Four "ratchet" tests freeze legacy global-state patterns: no new bare server_args.x = ... assignments, ServerArgs.override call sites can only shrink, the legacy get_global_server_args accessor is frozen, and module-level global statements are pinned by name. A two-way coverage test keeps NS() annotations and namespace bags in sync. Model-specific config tweaks are declared, never assigned: MODEL_OVERRIDES["Arch"] = {...} / @register_model_override("Arch") in arg_groups/overrides.py.

environ.py: the typed env-var registry

python/sglang/srt/environ.py is deliberately stdlib-only (it loads before torch). One Envs class (line 239) holds typed descriptors — EnvBool/EnvInt/EnvFloat/EnvStr/ EnvTuple/EnvJSON, plus *WithAlias variants for deprecated names — and the singleton is envs = Envs(). Legacy SGL_* keys are rewritten to SGLANG_* at import time with a DeprecationWarning (_convert_SGL_to_SGLANG(), line 1322). Tests use the context-manager envs.SGLANG_X.override(value), which restores prior state exactly.

`if envs.SGLANG_X:` raises — by design Reading a flag without .get() is a hard error, not a silent truthy-object bug: 
    def __bool__(self):
        raise RuntimeError(
            "Please use `envs.YOUR_FLAG.get()` instead of `envs.YOUR_FLAG`"
        )

Stall detection and death detection point in opposite directions: a stuck scheduler loop SIGQUITs the parent; a dead child makes the parent SIGQUIT itself (SubprocessWatchdog, added for NCCL C++ terminations that skip Python cleanup — issue #18421). Both dump py-spy stacks first so the hang site is preserved.
  • Hard + soft watchdogs. The scheduler installs a hard watchdog with the device-specific timeout (scheduler.py:1187) and, optionally, a log-only soft one (--soft-watchdog-timeout, scheduler.py:1179). Watchdog.create() returns a no-op when unconfigured, and Watchdog.disable() is a context manager for legitimately long operations (you saw the detokenizer use it in chapter 01).
  • kv_canary (python/sglang/srt/kv_canary/): production-grade KV-corruption detection. install_canary() patches the KV pool so every KV write also writes a canary record (expected token id/position, optional partial hash of the first 16 bytes of real KV via RealKvHashMode.PARTIAL). Verification kernels check HEAD/TAIL slots each forward, plus an optional every-N-step sweep of all radix-tree-held slots. CanaryMode: log is designed to run in production; raise turns violations into a RuntimeError. A perturb/ package deliberately injects corruption to self-test the detector, and a token_oracle/ predicts expected input tokens. Gotcha: EAGLE draft pools get kv_token_id_vs_position_offset = 1 because their rotated input_ids store K/V for position p+1 (kv_canary/api.py).
  • Crash dumps & CUDA coredumps. debug_utils/cuda_coredump.py enables CUDA coredumps via SGLANG_CUDA_COREDUMP; SGLANG_TEST_STUCK_* knobs exist purely to test stuck detection.
  • SchedulerInputBlocker (managers/scheduler_input_blocker.py): queues incoming requests while weights update, releasing them via a PollBasedBarrier once all ranks unblock.

12.6Support subsystems: the long tail

Each of these is a self-contained subsystem that didn't warrant its own chapter — one crisp paragraph each, all under python/sglang/srt/ unless noted.

state_capturer/ — routed-experts replay for RL. Captures per-layer top-k routing decisions during forward into a preallocated (max_batch, num_layers, topk) int32 GPU ring buffer with a pinned host mirror. RoutedExpertsCapturer (routed_experts.py:24) records which experts each token was routed to and returns them in meta_info["routed_experts"]; indexer_topk.py does the same for DSA indexer top-k. Consumers: RL/distillation pipelines that need expert-routing replay.

plugins/ — an AOP hook registry. Plugins discovered via Python entry points register hooks against dotted paths (e.g. "sglang.srt.managers.scheduler.Scheduler.schedule"); apply_hooks() runs once before the engine serves, and HookSource records which plugin/distribution registered each hook for accountable logging.

class HookType(Enum):
    """Types of hooks that can be applied to functions or classes."""

    BEFORE = "before"  # Execute before original; can modify args
    AFTER = "after"  # Execute after original; can modify return value
    AROUND = "around"  # Wrap original; full control over execution
    REPLACE = "replace"  # Replace the original function or class entirely

weight_cache/ — the Weight Cache Daemon. A persistent per-GPU process that "holds post-quantized, TP-sharded model weights in GPU memory and serves them via CUDA IPC handles … over a Unix socket to requesting engine processes" (daemon.py:1–9). One daemon per TP rank; it validates CacheConfig compatibility before serving. Result: engine restarts skip the whole disk → shard → quantize pipeline and become near-instant.

checkpoint_engine/ — start dummy, become real. Integration with the checkpoint-engine RL weight-update flow: the server starts with --load-format dummy --checkpoint-engine-wait-weights-before-ready, then python -m sglang.srt.checkpoint_engine.update broadcasts real weights in before the server reports ready.

session/ — server-side multi-turn state. /open_session creates a Session holding a tree of SessionReqNodes in the scheduler; each turn is a node and branching from an earlier turn is supported. Requests carry session_params to append to a node, reusing accumulated tokens instead of resending history. streaming_session.py's StreamingSession implements BasePrefixCache so held sessions pin their KV — surfaced in the num_streaming_sessions / streaming_session_held_tokens metrics.

debug_utils/ — dump, compare, truncate, simulate. The tensor dumper.py is an HTTP-controllable dump server (exposed as /dumper/{method}); dump_comparator.py / text_comparator.py diff dumps between runs (the standard "which layer diverged first" workflow); plus cuda_coredump.py, model_truncator.py, a schedule_simulator/, and a source_patcher/.

sglang/kernel_api_logging.py (top level) — logs every kernel API call for debugging CUDA crashes: the last logged call before a crash localizes the failing kernel. sglang/profiler.py — client-side helper that drives /start_profile / /stop_profile against a running server. sglang/check_env.py — environment doctor: prints versions, GPU topology, and NCCL/driver info for bug reports.

sglang/multimodal_gen/ — "SGLang Diffusion". A separate image/video generation framework (Wan, FLUX, Qwen-Image and friends) sharing the repo but not the autoregressive engine covered in chapters 01–11. The sglang serve CLI auto-detects diffusion models and routes them here (chapter 01's entry-point diagram). Don't confuse it with srt/multimodal/, which is multimodal understanding (VLM input processors, chapter 05).

batch_invariant_ops/ — batch-size-invariant torch op replacements for deterministic inference: identical results regardless of how requests get batched (see chapter 06). dllm/ — diffusion-LLM decoding support (pluggable decode algorithms like low_confidence.py, scheduler/req mixins); the text-diffusion sibling of the speculative techniques in chapter 09.

12.9Notable facts & gotchas

  • The health probe measures the heartbeat, not the probe. /health passes as soon as last_receive_tstamp advances — any detokenizer output within 20 s counts, so a busy-but-alive server never pays for health checks (the probe request is simply never scheduled).
  • Prometheus import order is a hard constraint: six files defer import prometheus_client with the identical comment because PROMETHEUS_MULTIPROC_DIR must be set first.
  • sglang:token_usage is a max, not a sum — the bottleneck across full/SWA/mamba pools; the code itself carries a FIXME that the name is misleading but renaming needs an API deprecation.
  • Two watchdog directions: loop stall → SIGQUIT the parent; dead child without Python cleanup → SIGQUIT self (SubprocessWatchdog, issue #18421). Both run pyspy_dump_schedulers() first.
  • The scheduler pushes per-iteration metrics over ZMQ PUB for Dynamo (FPM_VERSION = 1) — a push channel entirely parallel to Prometheus.
  • DP-cooperation metrics deliberately omit num_decode_ranks to avoid Prometheus label-cardinality explosion; derive it as world_size − num_prefill_ranks (metrics_collector.py:173).
  • if envs.SGLANG_X: raises by design — the descriptor's __bool__ is a RuntimeError, forcing .get().
  • managers/configure_logging.py is not a manager — it's a 70-line CLI client that POSTs to the /configure_logging endpoint.
  • kv_canary ships its own saboteur: the perturb/ package injects corruption on purpose so the detector can be validated end-to-end; it's incompatible with piecewise-CUDA-graph prefill (asserted in install_canary).
  • Two "multimodal" trees: srt/multimodal/ = understanding (VLM inputs); top-level multimodal_gen/ = SGLang Diffusion, a separate image/video generation stack.

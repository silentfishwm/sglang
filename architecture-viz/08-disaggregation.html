Phase IV · Scaling Out

08 · Serving at Scale: PD Disaggregation, HiCache & the Model Gateway

One GPU node is never the whole story. This chapter covers the machinery that turns SGLang instances into a fleet: splitting prefill and decode onto separate servers with RDMA KV transfer, spilling the KV cache into host memory and remote storage (HiCache), and the Rust model gateway that routes requests across all of it — plus the exotic alternative of splitting one GPU's SMs between prefill and decode.

8.1Why split prefill from decode?

Prefill and decode are opposite workloads sharing one engine. Prefill is compute-bound: thousands of tokens in one forward pass, saturating the SMs for hundreds of milliseconds. Decode is latency-bound: one token per request per step, dominated by memory bandwidth, and users feel every hiccup as inter-token latency. Colocated, they interfere — every big prefill stalls all running decodes for that iteration (chunked prefill from chapter 02 softens this, but doesn't eliminate it, and it costs prefill throughput). The fix, popularized by Mooncake (Moonshot AI's serving stack, FAST'25 best paper) and DistServe, is to run prefill-only and decode-only server pools and ship the KV cache from P to D over RDMA. Each pool then scales, batches and parallelizes independently — prefill wants max-throughput batching and can even use a different TP size than decode.

8.2The PD architecture in code

Everything lives under python/sglang/srt/disaggregation/. A server's role is DisaggregationMode — NULL (colocated, the default), PREFILL, or DECODE — selected by --disaggregation-mode. The data mover is a pluggable TransferBackend: 

class DisaggregationMode(Enum):
    NULL = "null"
    PREFILL = "prefill"
    DECODE = "decode"

class TransferBackend(Enum):

    MORI = "mori"

Four moving parts make the P↔D rendezvous work:

  • Bootstrap server — an aiohttp app started by the prefill scheduler (TP rank 0) on --disaggregation-bootstrap-port (default 8998). Prefill ranks PUT /route their topology (attn TP/DP/PP rank & size, rank IP/port, page size, KV dtype) at startup via register_to_bootstrap() (common/conn.py:674); decode ranks GET /route to discover which prefill ranks hold their KV shard — this is where asymmetric TP between P and D gets resolved.
  • bootstrap_room — an integer correlation id minted by the router and injected into the request JSON sent to both sides (bootstrap_host, bootstrap_port, bootstrap_room fields on GenerateReqInput, io_struct.py). It keys every handshake and transfer table end to end.
  • KV sender/receiver — per-request objects from get_kv_class(transfer_backend, KVClassType.SENDER/RECEIVER) (utils.py:558), created by the queues below.
  • MetadataBuffers (utils.py:262) — pinned tensors carrying the first output token, cached-token count, logprobs and optional hidden states from P to D, indexed by a ReqToMetadataIdxAllocator.

def event_loop_normal_disagg_prefill(self: Scheduler) -> None:
    """A normal scheduler loop for prefill worker in disaggregation mode."""
    while True:
        # Receive requests
        recv_reqs = self.request_receiver.recv_requests()
        self.process_input_requests(recv_reqs)
        if self._engine_paused:
            continue
        self.waiting_queue.extend(
            self.disagg_prefill_bootstrap_queue.pop_bootstrapped()
        )

Per-request transfer state is a five-state machine, KVPoll (base/conn.py:89): Failed=0 → Bootstrapping=1 → WaitingForInput=2 → Transferring=3 → Success=4. Because every TP rank has its own sender/receiver, ranks agree on a state via a MIN all-reduce (poll_and_all_reduce, utils.py:161) — one lagging rank holds the whole request back, and one Failed rank fails it everywhere.

The reason D preallocates KV for the entire input before any bytes move is a deadlock guard. Decode can normally retract running requests to free memory (chapter 02), but a request whose KV is mid-transfer cannot be retracted — so pop_preallocated only admits a request if retracting the currently-running batch could always free enough room: 

# We need to make sure that the sum of inflight tokens and allocatable tokens is greater than maximum input+output length of each inflight request
# Otherwise it is possible for one request running decode out of memory, while all other requests are in the transfer queue that cannot be retracted.
retractable_tokens = sum(
    len(r.origin_input_ids) + len(r.output_ids)
    for r in self.scheduler.running_batch.reqs
)
Recovery paths Three escape hatches keep the pipeline from wedging: decode can retract transferred requests back into DecodePreallocQueue (resume_retracted_reqs, decode.py); it can rebootstrap — POST /generate directly to the prefill server's advertised prefill_http_port to recompute KV from scratch (common/conn.py:102); and with --optimistic-prefill-attempts N the prefill side runs the forward before the handshake completes, releasing and re-queueing via optimistic_release_and_requeue (prefill.py:1254) if the receiver still isn't ready.

8.4The KV transfer abstraction

Backends plug into four abstract classes in python/sglang/srt/disaggregation/base/conn.py, all constructed through get_kv_class(): a per-scheduler BaseKVManager (owns registered memory + transfer threads), per-request BaseKVSender / BaseKVReceiver, and a BaseKVBootstrapServer. The manager is fed a KVArgs struct — raw device pointers, lengths and item sizes for every KV layer, the aux metadata buffers, and auxiliary state tensors (StateType: Mamba conv/ssm, SWA, DSA and friends — hybrid models transfer more than plain KV pages). All real backends share CommonKVManager/Sender/Receiver/BootstrapServer (common/conn.py), which implements bootstrap registration, ZMQ control-plane sockets between ranks, and the rank-mapping math for heterogeneous P/D TP sizes.

8.5HiCache: the KV cache grows three tiers

Disaggregation ships KV sideways; HiCache ships it down the memory hierarchy. With --enable-hierarchical-cache, the radix tree from chapter 03 becomes a HiRadixCache (mem_cache/hiradix_cache.py:76) whose nodes can live in three places: L1 device KV pool, L2 pinned host memory (HostKVCache pools in mem_cache/memory_pool_host.py, sized device_size × --hicache-ratio, default 2.0), and L3 external storage. A node with value=None but host_value set is "evicted but backuped"; a node known only by its hash_value chain lives in storage. The data mover is HiCacheController (managers/cache_controller.py:225).

def write(
    self,
    device_indices: torch.Tensor,
    priority: Optional[int] = None,
    node_id: int = -1,

    Back up KV caches from device memory to host memory.

The clever part is the per-layer overlap on load-back. The whole family is tuned by --hicache-* flags: --hicache-ratio / --hicache-size (L2 sizing), --hicache-write-policy (write_through default · write_through_selective backs up only nodes whose hit_count crosses a threshold · write_back), --hicache-mem-layout (page_first default, layer_first, …), --hicache-io-backend (kernel | direct), --hicache-storage-backend (the 10 L3 backends), --hicache-storage-prefetch-policy (best_effort | wait_complete | timeout default, with a linear time budget per Ki-token) and --hicache-storage-backend-extra-config. In PD deployments HiCache composes with disaggregation: decode_hicache_mixin.py hooks the decode prealloc/transfer queues, and --disaggregation-decode-enable-radix-cache lets D match local prefixes so only the non-cached suffix is transferred.

8.6The Rust model gateway

sgl-model-gateway/ (formerly sgl-router; the pip package is still sglang_router, built from bindings/python, and the binary installs as sgl-model-gateway with aliases smg and amg — Cargo.toml) is a standalone Rust control-and-data plane in front of the fleet: OpenAI-compatible endpoints, worker registry with health checks and per-worker circuit breakers, retries with exponential backoff + jitter, token-bucket rate limiting with fair queuing, Kubernetes service discovery (pod selectors, with separate prefill_selector / decode_selector and a bootstrap-port annotation in PD mode), an MCP client, and a gRPC pipeline that talks straight to SRT gRPC schedulers using a native Rust tokenizer plus reasoning/tool-call parsers.

Don't confuse it with rust/ The repo has two Rust worlds. sgl-model-gateway/ is the out-of-process router. rust/ is a separate workspace of in-process PyO3 crates: sglang-server (a Rust HTTP frontend embedded inside the Python scheduler process — chapter 01's SGLANG_RUST_SERVER=1), sglang-grpc (in-process gRPC server) and sglang-mm (Rust multimodal preprocessing, compiled as sglang.srt.multimodal._core).

select_pd_pair() (pd_router.rs:972) filters the worker registry by WorkerType::Prefill/Decode, applies each pool's policy (separate --prefill-policy / --decode-policy override --policy), then dispatches the same body to both workers concurrently — streaming from decode and merging prefill logprobs into the response.

Routing policies live in src/policies/ — the PolicyConfig enum (config/types.rs:254) offers random, round_robin, cache_aware, power_of_two, bucket, manual (sticky sessions via X-SMG-Routing-Key), consistent_hashing, and prefix_hash. The flagship is cache-aware routing: the gateway never asks workers what they have cached. Instead it keeps an approximate, character-level radix tree per worker (policies/tree.rs) of the text it has already routed there — a client-side shadow of each worker's real RadixCache (chapter 03). The algorithm:

  1. If load is imbalanced — (max−min) > balance_abs_threshold and max > min × balance_rel_threshold (cache_aware.rs:401) — fall back to shortest-queue routing. Cache affinity never wins against a hot spot.
  2. Otherwise tree.prefix_match_with_counts(text); route to the best-matching worker if match_rate > cache_threshold, else to the worker with the smallest tree (most free cache).
  3. Insert the text into the chosen worker's tree; a background task LRU-evicts leaves down to max_tree_size every eviction_interval_secs.

8.7GPU multiplexing: PD split on a single GPU

python/sglang/srt/multiplex/ is the opposite extreme: instead of two fleets, one GPU is spatially partitioned with CUDA green contexts. Enabled by --enable-pdmux ("Enable PD-Multiplexing, PD running on greenctx stream"), divide_sm() computes valid (prefill_sm, decode_sm) partitions per architecture (SM90: multiples of 8, min 8), and initialize_stream_groups builds --sm-group-num (default 8) stream groups — group 0 is a full-GPU stream for prefill, the last is full-GPU for decode, and the middle groups pin prefill and decode kernels to disjoint SM sets running concurrently: 

STREAM_GROUPS = []
STREAM_GROUPS.append(

SchedulerMultiplexMixin.event_loop_pdmux (multiplexing_mixin.py:101) runs one scheduler that keeps the decode running_batch on the decode stream while executing a split_prefill_batch in bounded slices (split_forward_token_budget, default 65536) on the prefill stream, and adjust_stream_groups re-picks the SM split as the decode batch size changes — intra-GPU PD disaggregation with zero KV transfer. The green-context streams come from sgl_kernel.spatial.create_greenctx_stream_by_value(prefill_sm, decode_sm, gpu_id) (chapter 06 covers sgl_kernel).

8.8Two small neighbors: connector/ and kv_canary/

python/sglang/srt/connector/ is remote storage, not PD transfer: URL-schemed connectors (redis://, s3://, az://, instance://) created by create_remote_connector(), with BaseFileConnector for pulling model weights from object stores and BaseKVConnector for remote KV get/set (safetensors-based serde in connector/serde/). It is orthogonal to the transfer backends of section 8.4.

python/sglang/srt/kv_canary/ is a production integrity watchdog for everything this chapter moves around: install_canary() (kv_canary/api.py:30) patches KV pools to write per-slot canary metadata (token id, position, optional hash of the real KV bytes) at write time and verify it at use time and in periodic sweeps — catching stale-page and index-corruption bugs that would otherwise surface as silently wrong text. Modes none/log/raise (CanaryMode), plus a deliberate fault-injection package (perturb/) to self-test detection.

Notable facts & gotchas

  • The first decode token is computed on the prefill server and shipped in MetadataBuffers with logprobs and optional hidden states — decode starts at token 2.
  • The bootstrap server is inside the prefill process (aiohttp on port 8998), and decode validates the bootstrap_room echoed back through the metadata buffer — a mismatch aborts with "Context corruption detected" (decode.py:1817).
  • KV transfer is page-aligned: send_kv_chunk() defers a partial trailing page to the next chunk, so chunked prefill and RDMA compose cleanly.
  • More than KV moves: StateType covers Mamba conv/ssm, SWA, DSA and other auxiliary state tensors, so hybrid models (chapter 03's Mamba pools) work under PD too.
  • TP ranks vote with MIN-allreduce on every KVPoll state, so a single failed rank fails the request everywhere instead of deadlocking the others.
  • The gateway's cache map is a guess: cache-aware routing maintains approximate char-level radix trees client-side (with mesh sync across gateway replicas). For exact knowledge, schedulers can publish BlockStored/BlockRemoved events over ZMQ (disaggregation/kv_events.py) to external routers.
  • The old Python mini load balancer is gone — CI fixtures now launch python3 -m sglang_router.launch_router --pd-disaggregation --mini-lb; the --mini-lb compat flag lives in the Rust CLI.
  • Encoder disaggregation is a third axis: encode_server.py runs a multimodal encoder-only server streaming embeddings to language servers — separate from the P/D KV path (and from connector/ remote storage).

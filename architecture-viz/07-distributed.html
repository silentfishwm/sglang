Phase IV · Scaling Out

07 · Distributed Execution: TP, PP, DP-Attention & Expert Parallelism

One GPU is never enough. This chapter maps SGLang's four axes of parallelism — tensor, pipeline, data, and expert — onto real process groups: how the torch.distributed world is shaped, how GroupCoordinator picks an allreduce implementation per tensor, why DeepSeek's MLA forced DP inside TP, how pipeline microbatches flow, and how EPLB shuffles expert weights while the server keeps serving.

7.1The parallelism taxonomy & the world-size math

The first thing to internalize: the torch.distributed world is exactly tp_size × pp_size. Nothing else. Data parallelism and expert parallelism are not extra dimensions of the NCCL world — they are either separate worlds (plain DP) or sub-slices of the TP group (DP-attention, EP). All group construction lives in python/sglang/srt/distributed/parallel_state.py (adapted from vLLM, which adapted it from Megatron-LM); ModelRunner enters through a single call, init_torch_distributed(...) in python/sglang/srt/distributed/bootstrap.py. 

world_size = (
    rank_offset + tp_size * pp_size if is_scale_joiner else tp_size * pp_size
)
rank = rank_offset + tp_size * pp_rank + tp_rank
Enforced, not implied initialize_model_parallel raises RuntimeError("world_size (...) is not equal to tensor_model_parallel_size (...) x pipeline_model_parallel_size (...)") if the invariant is violated (python/sglang/srt/distributed/parallel_state.py:2251).

rank = tp_size * pp_rank + tp_rank, so TP groups are contiguous blocks (group i = ranks [i·tp, (i+1)·tp)) and PP groups are strided (group i = range(i, world_size, world_size // pp)) — the classic Megatron layout, spelled out in the docstring of initialize_model_parallel (parallel_state.py). The PP group is created with use_custom_allreduce=False — "pipeline parallel does not need custom allreduce".

7.2GroupCoordinator: one group, many transports

Every process group is wrapped in a GroupCoordinator (parallel_state.py:221): "PyTorch ProcessGroup wrapper for a group of processes… It can route the communication to a specific implementation (e.g. switch allreduce implementation based on the tensor size and cuda graph mode)." Each coordinator holds two torch process groups — a device_group (NCCL/HCCL/mooncake) for tensor traffic and a gloo cpu_group for CPU-side coordination — plus a menu of optional fast-path communicators, each created only if its use_* hint is set and world_size > 1:

  • pynccl_comm — PyNcclCommunicator, ctypes-loaded NCCL that works inside CUDA graph capture and supports the NCCL symmetric-memory window (device_communicators/pynccl.py).
  • ca_comm — CustomAllreduce, one-shot/two-shot IPC allreduce for small tensors (custom_all_reduce.py).
  • qr_comm — QuickAllReduce, ROCm-only quantized allreduce (FP/INT8/INT6/INT4 regimes), "designed as a complement to custom allreduce" for large tensors.
  • pymscclpp_comm, torch_symm_mem_comm (TorchSymmMemCommunicator), and platform communicators (hpu/xpu/npu_communicator).
  • mq_broadcaster — MessageQueue.create_from_process_group(cpu_group, 1 << 22, 6), a shared-memory ring buffer (shm_broadcast.py) for broadcasting Python objects to local TP ranks without touching NCCL.

def should_custom_ar(self, inp: torch.Tensor):
    if self.disabled:
        return False
    inp_size = inp.numel() * inp.element_size()
    # custom allreduce requires input byte size to be multiples of 16
    if inp_size % 16 != 0:
        return False
    if not is_weak_contiguous(inp):
        return False
    # for 4 or more non NVLink-capable GPUs, custom allreduce provides
    # little performance improvement over NCCL.
    if not _is_hip:
        if self.world_size == 2 or self.full_nvlink:
            return inp_size <= self.max_size
        return False
The size caps CustomAllreduce._MAX_CAR_SIZE = 8192 * 1024 (8 MiB) on CUDA, 2 * 8192 * 1024 (16 MiB) on ROCm ("crossover is at 16MB buffer size for ROCm"), 16 * 8196 * 1024 (~128 MiB) on MUSA; supported world sizes are [2, 4, 6, 8] (custom_all_reduce.py:41). Above the cap, NCCL wins — unless ROCm's QuickAllReduce takes over with its per-(dtype, world-size, quant-regime) minimum-size table. P2P capability is verified empirically: gpu_p2p_access_check spawns producer/consumer processes because "P2P capability detection can be flaky on some platforms", caching results to a JSON file keyed by CUDA_VISIBLE_DEVICES (custom_all_reduce_utils.py).

7.3DP-attention: the DeepSeek MLA story

Why does DP live inside TP at all? DeepSeek-style MLA has a single latent KV head. Under pure TP-8, attention weights shard fine but the KV cache cannot — every one of the 8 GPUs stores an identical full copy. DP-attention (--enable-dp-attention) fixes this: split the TP group into dp_size attention replicas, give each replica its own requests and its own KV cache (no duplication), and only merge tokens back into one global batch for the MoE/dense-MLP part, which stays TP/EP across the full world. Replicas can even be in different phases — one prefilling while another decodes or idles.

LayerCommunicator/ScatterMode (layers/communicator.py:197) names the data layouts. With TP=4, DP=2 and sequences a,b on DP0 and c,d on DP1: attention runs in TP_ATTN_FULL ([ab, ab, cd, cd] across the four ranks), the MoE runs in FULL ([abcd, abcd, abcd, abcd]). The transitions are dp_gather_partial before the MLP and dp_scatter / dp_reduce_scatter_tensor after (layers/dp_attention.py:789,805,827).

DpPaddingMode (dp_attention.py:72): MAX_LEN pads every rank to max(global_num_tokens) and uses a pure all-gather (symmetric-memory friendly, the CUDA-graph default); SUM_LEN allocates sum(global_num_tokens) rows and does zero-fill + memcpy + all-reduce of disjoint slices (preferred for prefill, where padding waste dominates). A gatherv path (SGLANG_DP_USE_GATHERV, optional fp8 wire format) avoids both. mask_dp_pad_moe_topk_ids sets pad rows' topk_ids to −1 so they are never dispatched to experts. 
# we choose the mode that minimizes the communication cost
# prefer MAX_LEN when communication cost is equal to enable symmetric memory
max_len = max(global_num_tokens)
sum_len = sum(global_num_tokens)
if sum_len * 2 >= max_len * dp_size:
    return cls.MAX_LEN
else:
    return cls.SUM_LEN

7.4Pipeline parallelism: microbatches over two transports

With --pp-size K each scheduler runs SchedulerPPMixin.event_loop_pp (python/sglang/srt/managers/scheduler_pp_mixin.py) instead of the normal loop from chapter 02. The design is unusual: instead of stage 0 broadcasting batch plans, every stage receives the raw request objects and re-runs the same scheduling decisions deterministically. Requests hop stage-to-stage as pickled Python objects over the gloo world group (point_to_point_pyobj, sent only from attn_tp_rank == 0); activations hop as PPProxyTensors over NCCL (pp_group.send_tensor_dict).

Why send `residual` too? PPProxyTensors (model_executor/forward_batch_info.py:1656) is just a dict of tensors. SGLang fuses each layer's output layer-norm with the next layer's residual add, so at a stage boundary the (hidden_states, residual) pair is still un-merged — both must travel. A FIXME in llama.py notes the residual could be eliminated by not fusing the norms at stage edges.

7.5Expert parallelism & EPLB: moving experts to the tokens

MoE all-to-all backends live in python/sglang/srt/layers/moe/token_dispatcher/ (deepep.py, mooncake.py, pplx.py, …; chapter 05 covers the layer math). The distributed-systems part is load balancing: token routing is learned, so some experts run hot and their EP ranks become stragglers. SGLang's answer is EPLB (python/sglang/srt/eplb/) — observe, recompute placement, migrate weights, all without stopping the server.

  • Observe: every DeepEP dispatch calls get_global_expert_distribution_recorder().on_deepep_dispatch_normal(...) / _low_latency(...) (layers/moe/token_dispatcher/deepep.py) — the ExpertDistributionRecorder keeps per-layer logical-expert counts in a circular buffer.
  • Decide: the scheduler calls EPLBManager.on_forward_pass_end() each iteration; an internal generator yields for eplb_rebalance_num_iterations (default 1000) passes, then runs rebalance() (eplb/eplb_manager.py:75,92). If average_utilization_rate_over_window already beats --eplb-min-rebalancing-utilization-threshold, it skips.
  • Place: ExpertLocationMetadata.init_by_eplb(...) recomputes physical_to_logical_map (layers, num_physical_experts) and logical_to_all_physical_map (eplb/expert_location.py:59-61) — physical slots (including the --ep-num-redundant-experts extras) can hold redundant copies of hot logical experts.
  • Migrate: ExpertLocationUpdater.update(...) P2P-moves expert weights between EP ranks chunk by chunk (--eplb-rebalance-layers-per-chunk), yielding back to the scheduler between chunks so serving continues.

7.7Multi-node launch, verified

From docs_new/docs/references/multi_node_deployment/multi_node.mdx — Llama 3.1 405B (fp16) as one tp=16 world across two 8-GPU nodes. Same command on both nodes except --node-rank: 

# replace 172.16.4.52:20000 with your own node ip address and port of the first node
python3 -m sglang.launch_server \
  --model-path meta-llama/Meta-Llama-3.1-405B-Instruct \
  --tp 16 \
  --dist-init-addr 172.16.4.52:20000 \
  --nnodes 2 \
  --node-rank 0

--dist-init-addr host:port becomes torch's tcp:// init method (bootstrap._resolve_dist_init_method; override with SGLANG_DISTRIBUTED_INIT_METHOD_OVERRIDE=env:// for external orchestrators). Which ranks a node runs: pp_size_per_node = max(pp_size // nnodes, 1) and tp_size_per_node = tp_size // nnodes_per_tp_group (data_parallel_controller.py); nodes with node_rank ≥ 1 run schedulers only (chapter 01). The SLURM recipe in the same doc uses --dist-init-addr "$NCCL_INIT_ADDR" --nnodes 2 --node-rank "$SLURM_NODEID". The DPA guide (docs_new/docs/advanced_features/dp_dpa_smg_guide.mdx) example: --tp-size 8 --dp-size 8 --enable-dp-attention — both flags required, dp_size must exceed 1 and divide tp_size.

7.8Notable facts & gotchas

  • Every NCCL group has a gloo shadow. Each GroupCoordinator carries a cpu_group "to allow direct coordination between processes through the CPU" — PP request forwarding, broadcast_object, and send_object/recv_object all ride gloo, keeping NCCL exclusively for tensors.
  • Group aliasing is pervasive. With --tp 8 --ep 8 (typical DeepSeek), _MOE_EP is _TP; _ATTN_CP aliases _TP when attn_cp_size == tp_size; and when attn_cp_size > moe_dp_size, _MOE_DP = _ATTN_CP so the existing DP allgather/scatter handles CP token sharing. Only unusual splits (and NPU, which needs a standalone EP group) create new communicators.
  • Plain DP ≠ DP-attention. --dp-size 4 alone gives 4 separate NCCL worlds behind a ZMQ load balancer; add --enable-dp-attention and the same flag instead carves 4 slices out of one TP world.
  • NCCL warm-up and memory sanity at boot: _prewarm_nccl runs one 1-element all-reduce to eat communicator-init latency (default on AMD), and _check_tp_memory_balance fails fast if any rank has <90% of the group's free memory — catching "another process is squatting on GPU 3" before a mid-load OOM (distributed/bootstrap.py).
  • _DpGatheredBufferWrapper uses class attributes, not contextvars — the per-forward buffer sizing must be visible under Dynamo tracing, and contextvars aren't traceable (layers/dp_attention.py:130).
  • Speculative decoding runs draft models at dp=1 semantics via the disable_dp_size() context manager during draft-worker init (chapter 09).
  • TBO overlap uses one shared comm stream with persistent CUDA events for dp_gather_partial_async / dp_reduce_scatterv_async — allocating events per-call exhausted the HSA signal pool on ROCm (dp_attention.py:858+).
  • The PP loop trades bandwidth for determinism: forwarding raw requests to every stage costs gloo traffic but removes any need for a batch-plan broadcast — each stage recomputes identical scheduling decisions.
  • Weight updates are globally serialized: the TokenizerManager takes model_update_lock.writer_lock, optionally aborts all in-flight requests, and bumps weight_version; every path is refused while the weight-cache daemon is attached, since CUDA-IPC-shared weights would corrupt all co-attached engines.

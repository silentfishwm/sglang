Phase V · Advanced Inference

09 · Speculative Decoding: EAGLE Trees, Diffusion LMs & Batch Overlap

Autoregressive decode reads every weight to produce one token — the GPU's compute units idle while HBM streams gigabytes. This chapter covers the three ways SGLang fills that idle time: speculative decoding (draft cheap, verify many tokens in one target forward), diffusion language models (denoise a whole block of tokens at once), and batch overlap (hide MoE all-to-all communication behind compute).

9.1Why speculate: decode is memory-bandwidth-bound

A decode step for one token must read all model weights from HBM but performs only a tiny matrix-vector multiply per weight tile — arithmetic intensity far below what the GPU can sustain. Verifying k candidate tokens in a single forward costs nearly the same wall-clock time as producing one, because the weight traffic dominates. Speculative decoding exploits this: a cheap draft proposes candidate continuations, and the target model scores them all in one batched forward. Every accepted draft token is a decode step you never had to run — and the output distribution is provably unchanged when acceptance follows rejection sampling.

SGLang's flagship family is EAGLE (feature-level autoregression: the draft head extrapolates on the target's hidden states, not just its sampled tokens, which makes drafts far more accurate than a standalone small LM). EAGLE-2 added dynamic draft trees: instead of a single chain, the draft expands a token tree and keeps the globally most probable nodes by joint (cumulative path) probability. EAGLE-3 trains the draft head on fused features from multiple target layers (low/mid/high) with direct token prediction — in this repo it is a separate algorithm value (EAGLE3) that reuses the same worker with a different hidden-state capture mode. All three share one iteration shape: draft a tree → verify it in one target forward → accept a root-path prefix → re-seed the draft.

Where the win comes from With --speculative-num-steps 3 --speculative-eagle-topk 4 --speculative-num-draft-tokens 8 (the auto-chosen Llama config is (5, 4, 8), DeepSeek-family MTP gets (3, 1, 4) — _auto_choose_speculative_params, python/sglang/srt/arg_groups/speculative_hook.py:795), each scheduler step runs 2 draft forwards + 1 target verify + 1 draft-extend, and typically commits 3–4 tokens instead of 1. The decode log's accept length (τ) is exactly that tokens-per-verify number.

Two source facts anchor the stepper. First, the draft loop runs only num_steps − 1 = 2 forwards — the first frontier comes free from last round's draft-extend logits:

Second, tree expansion keeps the global top-topk frontier by joint path probability: at step i>0, _select_top_k_tokens_later (spec_utils.py:300) computes expand_scores = scores.unsqueeze(2) * topk_p.view(-1, topk, topk) — each of the 4 frontier nodes proposes 4 children (16 candidates), each child's score is parent-score × child-probability — then fast_topk(...) keeps the best 4. In our example "," (0.55) × "the" (0.5) = 0.275 beats "." (0.20) × "It" (0.6) = 0.12. All 4 + 16 + 16 = 36 scored candidates go to organize_draft_results (eagle_utils.py:100), which takes torch.topk(score_list, num_draft_token − 1 = 7), sorts the winning indices, and gathers the 7 draft tokens plus their parent_list. With topk=1 the tree degenerates to a chain and a preallocated fast path (_rebuild_topk1_chain_buffers) skips the scoring machinery entirely.

9.5Verification math: greedy walk vs. sampling

eagle_sample (eagle_utils.py:646) applies relaxed penalties, logit bias and grammar masks to the bs×8 target logits, then branches on the sampling mode. Greedy (all requests greedy — and always on CPU/NPU/HIP/XPU): take the target argmax at every tree position, then walk the tree from the root; at each accepted node, scan its children via retrieve_next_token / retrieve_next_sibling for a child whose draft token equals the target's prediction at the current node. Match → descend; no match → stop. The target's prediction at the last accepted node becomes the new bonus token.

Naming discipline: accept vs. correct The kernels count num_correct_drafts — drafts only, bonus excluded (the sgl_kernel kwarg keeps the frozen legacy name accept_token_num). eagle_sample returns num_correct_drafts + 1, which callers store as accept_lens — bonus included. In the worked example: 3 correct drafts (",", "the", "capital"), accept_lens = 4 with the bonus "of". Acceptance per verify is bounded by EagleVerifyInput.max_tree_depth = spec_steps + 1 (the accept_index row width) — at most 4 here, at least 1 (the root always accepts). The paper-convention metrics keep their own semantics: accept_rate α excludes the bonus, accept_length τ includes it.

Adaptive speculation — including steps = 0 With --speculative-adaptive, AdaptiveController (adaptive_runtime_state.py:61) watches measured acceptance and batch size, and EAGLEWorkerV2.build_adaptive_runtime_state / apply_runtime_state hot-swap a pre-captured SpecRuntimeState — attention backends + CUDA graph runners — per candidate step count. Distinctive to this repo: speculative_num_steps == 0 is a valid state that degenerates to plain decode via EAGLEWorkerV2._build_trivial_verify_input (eagle_worker_v2.py:1176) — a 1-node "tree" rooted at the previous bonus token — and by default still runs draft-extend to keep the draft KV warm (SGLANG_SPEC_SKIP_ZERO_STEP_DRAFT_EXTEND opts out). Overlap scheduling relays draft state across iterations through a FutureMap (SpeculativeAlgorithm.create_future_map), and the worker exposes war_fastpath_runner — the step's last shared-buffer reader (the draft-extend runner) — for the scheduler's write-after-read barrier.

9.7dLLM: diffusion language models (srt/dllm/)

A completely different attack on the same bandwidth wall: block diffusion models generate a whole block of tokens by iterative mask-denoising instead of one token per forward. Enabled by --dllm-algorithm <Name> (+ optional --dllm-algorithm-config YAML). DllmConfig.from_server_args (dllm/config.py) hard-codes per-architecture block geometry: LLaDA2MoeModelLM → block_size 32, mask_id 156895; SDARForCausalLM / SDARMoeForCausalLM → block_size 4, mask_id 151669. Each round appends a block of [MASK] tokens (ForwardMode.DLLM_EXTEND, forward_batch_info.py:122) and denoises it.

Algorithms are auto-discovered by module scan (algorithm/__init__.py, keyed by class name): LowConfidence unmasks every masked position whose argmax confidence exceeds a threshold (default 0.95), falling back to the single most confident position when nothing passes; JointThreshold is a vectorized variant that can also re-edit already-unmasked tokens (edit_threshold, bounded by max_post_edit_steps, with repetition penalty penalty_lambda).

confidence = torch.gather(probs, dim=-1, index=x.unsqueeze(-1)).squeeze(-1)
confidence = torch.where(block_mask_index, confidence, -float("inf"))

transfer_index = confidence > self.threshold
has_transfer = transfer_index.sum(dim=1) > 0
top1_indices = torch.argmax(confidence, dim=1)
batch_indices = torch.arange(batch_size, device=top1_indices.device)
top1_mask = torch.zeros_like(transfer_index, dtype=torch.bool)
top1_mask[batch_indices, top1_indices] = True
transfer_index = torch.where(
    has_transfer.unsqueeze(-1), transfer_index, top1_mask
)

9.8Batch overlap: TBO and SBO (srt/batch_overlap/)

Both target the MoE communication bottleneck in expert-parallel deployments: DeepEP dispatch/combine all-to-alls leave the GPU idle while traffic is in flight. Two-Batch Overlap (--enable-two-batch-overlap) splits one ForwardBatch into two micro-batches ("child a" / "child b") and interleaves their layer stages: while A waits on its all-to-all, B computes. compute_split_seq_index (two_batch_overlap.py:78) picks the tbo_split_seq_index: decode and target-verify batches split at half the requests ((num_tokens // token_num_per_seq) // 2, where target-verify uses spec_info.draft_token_num per seq — TBO composes with EAGLE, and split_spec_info slices the EagleVerifyInput per child); extend batches split by balanced token sum, with a "two-chunk" mode that cuts one sequence across both children when the distribution is too skewed (--tbo-token-distribution-threshold, default 0.48).

Execution: models call model_forward_maybe_tbo; OperationsStrategy.init_new_tbo (operations_strategy.py:34) compiles each decoder layer (DeepseekV2 / Qwen3-MoE / DeepseekV4 families) into an ordered op list — e.g. op_comm_prepare_attn, self_attn.op_prepare, self_attn.op_core, op_comm_prepare_mlp, mlp.op_gate, op_select_experts, op_dispatch_a, YieldOperation(), op_dispatch_b, op_experts, op_combine_a, YieldOperation(), op_shared_experts, op_combine_b, op_output, op_comm_postprocess_layer — and execute_overlapped_operations runs two _StageExecutors offset by tbo_delta_stages (0 for prefill, 2 for decode), ping-ponging at every YieldOperation: cooperative coroutine scheduling of two micro-batches on one stream, with deep_gemm_num_sms reserving SMs for compute while DeepEP owns the rest. 

executor_a = _StageExecutor("a", stages_a, inputs=inputs_a, child_ctx=child_ctx_a)
executor_b = _StageExecutor("b", stages_b, inputs=inputs_b, child_ctx=child_ctx_b)

for _ in range(delta_stage):
    executor_a.next()

for _ in range(executor_a.num_stages - delta_stage):
    executor_a.next()
    executor_b.next()

for _ in range(delta_stage):
    executor_b.next()

assert executor_a.done and executor_b.done
return [executor_a.output, executor_b.output]

Notable facts & gotchas

  • Draft cost is num_steps − 1 forwards, not num_steps: the first frontier comes free from draft-extend logits (the break in eagle_worker_v2.py:597).
  • accept_lens includes the bonus; num_correct_drafts does not. Kernels count drafts only (frozen sgl_kernel kwarg accept_token_num); eagle_sample returns num_correct_drafts + 1; the scheduler recovers per-request correct drafts as accept_lens[i] − 1.
  • Sampling verify broadcasts predict / accept_index / num_correct_drafts from TP rank 0 to prevent cross-rank divergence from floating-point nondeterminism (eagle_utils.py:828).
  • TARGET_VERIFY reuses the decode CUDA graph family — it is "essentially a fixed sequence length prefill/extend with full cuda graph support" (spec_info.py:226), bucketed on bs × num_draft_tokens tokens.
  • Grammar decoding overlaps with drafting via a scheduler grammar barrier; the FSM advances inside verify and any post-terminal accepted suffix is retro-truncated on the CPU side.
  • Adaptive spec pre-captures a SpecRuntimeState per candidate step count and hot-swaps backends + graphs; steps=0 still runs draft-extend by default to keep draft KV warm (SGLANG_SPEC_SKIP_ZERO_STEP_DRAFT_EXTEND opts out).
  • page_size > 1 with topk > 1 needs per-branch page-aligned draft regions and duplication of the prefix tail page into each branch (duplicate_prefix_tail_to_draft_branches, eagle_worker_common.py:58).
  • dLLM FDFO speaks the spec-decoding scheduler contract (accept_length_per_req_cpu = block_size or 0), so batch-result plumbing is shared between EAGLE and diffusion blocks.
  • TBO's split point is spec-aware (get_token_num_per_seq returns spec_info.draft_token_num for target-verify), so EAGLE verify batches split evenly by request across the two micro-batches; DSpark adds per-request ragged verify lengths (RaggedVerifyMode cap-accept / compact) with its own spec_block_accept_length metric.
  • There is no V1 EAGLE worker. EAGLE / EAGLE3 / STANDALONE / MTP always instantiate the V2 worker; with overlap disabled the scheduler simply drives it synchronously (spec_info.py:278).
